一、可用Skills总结（按功能分类）

  1.1 学习和知识管理类

  /learn（ecc:learn）
  - 提取会话中的可复用模式
  - 保存为候选skill或guidance
  → Session Agent调用：会话结束时提取模式

  /learn-eval（ecc:learn-eval）
  - 提取模式并自我评估质量
  - 决定保存到Global还是Project
  → Session Agent调用：质量评估后再保存

  /skill-create（ecc:skill-create）
  - 从git历史提取coding patterns
  - 生成SKILL.md
  → Project Agent调用：分析项目代码模式

  1.2 项目分析类

  /plan（ecc:plan）
  - 重述需求、评估风险、创建实施计划
  → Project Agent调用：分析项目架构

  /plan-prd（ecc:plan-prd）
  - 生成PRD（problem-first）
  → Project Agent调用：提取项目需求文档

  /code-review（ecc:code-review）
  - 代码审查（本地未提交或GitHub PR）
  → Project Agent调用：提取代码质量指标

  /update-codemaps（ecc:update-codemaps）
  - 扫描项目生成架构codemaps
  → Project Agent调用：生成项目结构图

  /codebase-onboarding（ecc:codebase-onboarding）
  - 深入分析codebase，生成onboarding文档
  → Project Agent调用：理解项目架构

  1.3 复习和问答类

  /deep-research（ecc:deep-research）
  - 深度研究问题（多模态搜索、综合）
  → Tech Explorer Agent调用：探索前沿技术

  /search-first（ecc:search-first）
  - 回答前先search确保准确性
  → Memory Agent调用：复习时查询知识

  /docs-lookup（ecc:docs-lookup）
  - 用Context7查询库文档
  → Tech Explorer Agent调用：学习新技术

  1.4 多模型协作类

  /multi-plan（ecc:multi-plan）
  - 创建多模型实施计划
  → Session Agent调用：复杂任务分解

  /multi-workflow（ecc:multi-workflow）
  - 运行完整的多模型workflow
  → 可以作为整个系统的orchestrator

  1.5 知识图谱类（Memory MCP）

  create_entities（memory MCP）
  - 创建知识节点
  → Memory Agent调用：保存新知识

  create_relations（memory MCP）
  - 创建知识关系
  → Memory Agent调用：关联知识

  search_nodes（memory MCP）
  - 语义搜索知识
  → Memory Agent调用：复习时查询

  read_graph（memory MCP）
  - 读取完整知识图谱
  → 可视化时调用

  1.6 GitHub集成类

  list_commits（github MCP）
  - 列出提交历史
  → Project Agent调用：分析项目时间轴

  search_code（github MCP）
  - 搜索代码
  → Project Agent调用：找技术实现

  create_issue（github MCP）
  - 创建issue
  → 可以用来创建"待复习"任务

  二、4个Agent的Skills调用设计

  Agent 1: Session Analyzer

  职责：分析会话、提取信息、触发其他Agent

  调用的Skills：
  1. /learn-eval（主要）
     - 每次会话结束自动调用
     - 提取可复用模式
     - 评估质量并保存

  2. /multi-plan（复杂会话）
     - 如果会话涉及复杂任务
     - 生成多步骤计划
     - 分发给其他Agent执行

  3. Context7 query-docs（需要时）
     - 会话中提到新技术时
     - 自动查询文档补充背景

  输入：会话历史（自动获取）
  输出：
  - 会话摘要（结构化JSON）
  - 学到的知识点列表
  - 涉及的项目列表
  - 新技术列表
  - 触发信号（通知其他Agent）

  无状态设计：
  - session_id作为显式状态
  - 每个会话独立分析
  - 不依赖之前的会话状态

  Agent 2: Memory Manager

  职责：管理知识图谱、生成复习计划

  调用的Skills：
  1. Memory MCP系列（核心）
     - create_entities：保存新知识
     - create_relations：建立关联
     - search_nodes：复习时搜索
     - read_graph：生成可视化

  2. /search-first
     - 复习时确保信息准确
     - 结合知识图谱和实时搜索

  3. Exa web_search_exa
     - 查找相关学习资源
     - 补充知识深度

  输入：
  - Session Agent的分析结果
  - 用户的复习请求

  输出：
  - 知识图谱更新结果
  - 复习计划（今天复习什么）
  - 知识缺口分析
  - 掌握程度评估

  无状态设计：
  - knowledge_id作为显式状态
  - 每个知识点独立存储
  - review_plan_id标识复习计划

  Agent 3: Project Tracker

  职责：追踪项目、提取亮点

  调用的Skills：
  1. /update-codemaps（项目分析）
     - 生成项目结构图
     - 提取模块关系

  2. /codebase-onboarding
     - 深入理解项目
     - 生成onboarding文档

  3. /skill-create
     - 提取项目的coding patterns
     - 保存为可复用skill

  4. /code-review
     - 分析代码质量
     - 提取优秀实践

  5. GitHub MCP系列
     - list_commits：时间轴
     - search_code：找实现
     - get_pull_request：了解设计决策

  输入：
  - 项目路径
  - Session Agent的通知（有新代码）

  输出：
  - 项目结构图
  - 技术栈分析
  - 面试亮点列表
  - 技术决策日志

  无状态设计：
  - project_id作为显式状态
  - analysis_id标识每次分析
  - 不依赖历史分析状态

  Agent 4: Tech Explorer

  职责：探索前沿技术、记录学习路径

  调用的Skills：
  1. /deep-research（核心）
     - 深度研究新技术
     - 多模态搜索（文档、代码、博客）

  2. /docs-lookup（Context7）
     - 查询官方文档
     - 获取最新API信息

  3. Exa系列（web搜索）
     - web_search_exa：找技术文章
     - web_fetch_exa：读全文

  4. /learn
     - 提取学习到的模式
     - 保存为学习笔记

  输入：
  - 技术名称/关键词
  - Session Agent的通知（探索了新技术）

  输出：
  - 技术调研报告
  - 学习资源列表
  - 技术雷达更新
  - 探索日志

  无状态设计：
  - exploration_id作为显式状态
  - 每次探索独立记录
  - tech_radar_version标识雷达版本

  5.1 Task 1: 项目代码扫描

  触发：用户「分析我的差旅系统」

  Project Agent返回Task：
  {
    "result": {
      "content": [{
        "type": "text",
        "text": "项目分析任务已启动"
      }],
      "_meta": {
        "io.modelcontextprotocol.tasks/taskHandle": {
          "task_id": "task-analysis-20260731-001",
          "status": "running",
          "progress": 0.0,
          "message": "扫描项目文件中..."
        }
      }
    }
  }

  Task执行流程：
  阶段1（10%）：扫描文件

  9.1 四个Agent的通信协议

  方案：事件驱动 + 消息队列（轻量级）

  不用真的MQ（RabbitMQ/Kafka），用内存队列：

  class AgentBus:
      """Agent之间的通信总线"""

      def __init__(self):
          self.subscribers = {}  # {event_type: [agent1, agent2, ...]}

      def subscribe(self, event_type, agent):
          """Agent订阅事件"""
          if event_type not in self.subscribers:
              self.subscribers[event_type] = []
          self.subscribers[event_type].append(agent)

      def publish(self, event):
          """发布事件"""
          event_type = event["type"]
          if event_type in self.subscribers:
              for agent in self.subscribers[event_type]:
                  agent.handle_event(event)

  事件类型：
  1. session_completed
     - 发布者：Session Agent
     - 订阅者：Memory Agent, Project Agent, Explorer Agent
     - 载荷：
       {
         "type": "session_completed",
         "session_id": "sess-20260731-143022",
         "summary": {
           "knowledge_learned": ["k-langchain-001"],
           "projects_touched": ["proj-travel-system"],
           "tech_explored": ["vLLM"]
         }
       }

  2. knowledge_updated
     - 发布者：Memory Agent
     - 订阅者：Project Agent（关联项目和技术）
     - 载荷：
       {
         "type": "knowledge_updated",
         "knowledge_id": "k-langchain-001",
         "operation": "create" | "update" | "delete"
       }

  3. project_analyzed
     - 发布者：Project Agent
     - 订阅者：Memory Agent（更新技术栈知识）
     - 载荷：
       {
         "type": "project_analyzed",
         "project_id": "proj-travel-system",
         "analysis_id": "analysis-001",
         "tech_stack": ["LangChain", "FastAPI", "React"]
       }

  4. tech_explored
     - 发布者：Explorer Agent
     - 订阅者：Memory Agent（创建新知识节点）
     - 载荷：
       {
         "type": "tech_explored",
         "exploration_id": "explore-vllm-20260731",

     → 触发MRTR（选择分析策略）

         "io.modelcontextprotocol.tasks/taskHandle": {

       }

     - 记录：本次会话分析了项目
