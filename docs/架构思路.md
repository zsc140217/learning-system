# Learning System AI-First 架构设计方案

> **核心理念**：让 LLM 成为编排者，MCP Server 只提供原子能力

---

## 一、架构对比

### 1.1 当前架构的问题

```
用户 → 自定义客户端（你的 LLM） → MCP Server: track_project()
                                     └─ 硬编码流程
```

**问题**：工作流固定、LLM 被动调用、无法复用 ECC 生态

### 1.2 目标架构（AI-first）

```
用户 → 客户端 LLM 读取 Skill → 动态决策 → 调用原子化 MCP Tools
```

**优势**：工作流可配置、LLM 主动编排、可复用 ECC

---

## 二、MCP Server 改造（原子化）

### 拆分项目分析工具

**旧**：track_project 做所有事
**新**：拆分为 4 个原子工具

- project/detect_framework()
- project/scan_structure()
- project/analyze_dependencies()
- project/extract_patterns()

### 简化技术探索

**旧**：explore_technology 包含路径构建
**新**：只保留 knowledge/search，路径由 Skill 构建

### 新增外部资源

- resource/query_docs (Context7)
- resource/web_search (Exa)

## 五、MCP Apps 设计

### 定义

服务端返回 UI 组件 → 客户端 iframe 渲染 → postMessage 通信

### 生命周期

触发 → 返回 uiTemplate → 渲染 → 交互 → 更新

### 客户端实现

```python
class MCPAppManager:
    async def render_app(self, app_spec):
        iframe = create_sandbox_iframe()
        iframe.post_message({"type": "init", "data": ...})
        iframe.on_message(self.handle_app_event)
    
    async def handle_app_event(self, event):
        if event["type"] == "node_selected":
            result = await mcp.call("knowledge/get_details", ...)
            iframe.post_message({"type": "update", "data": result})
```

### 示例：知识图谱可视化

服务端返回 vis.js HTML → 用户点击节点 → postMessage → 获取详情

## 六、客户端完整模块

### 核心架构

```python
class LearningSystemClient:
    def __init__(self):
        self.state = ClientStateManager()
        self.mcp = MCPClient()
        self.llm = YourLLMAPI()
        self.skills = SkillManager()
        self.apps = MCPAppManager()
        self.tasks = TaskManager()
        self.mrtr = MRTRHandler()
```

### 任务管理器（长任务）

```python
class TaskManager:
    async def submit_task(self, tool_name, args, ui_callback):
        result = await mcp.call_tool(tool_name, args)
        if "taskHandle" in result["_meta"]:
            asyncio.create_task(self.poll_task(task_id, ui_callback))
```

### MRTR 处理器（二次确认）

```python
class MRTRHandler:
    async def handle_input_required(self, tool_name, args, result):
        input_required = result["_meta"]["io.modelcontextprotocol/inputRequired"]
        user_input = await ui.show_confirmation(...)
        return await mcp.call_tool(tool_name, {
            **args, 
            "request_state": input_required["requestState"],
            **user_input
        })
```

## 七、完整场景

### 场景1：面试准备
LLM 读 skill → 询问目标 → 并行调用工具 → 生成材料 → 保存

### 场景2：知识图谱
调用工具 → 检测 uiTemplate → 渲染 App → 用户交互 → 更新

### 场景3：深度分析
提交长任务 → 显示进度条 → 后台轮询 → 完成返回

### 场景4：删除节点
第一轮返回确认 → 显示对话框 → 第二轮执行

## 八、技术选型

### 推荐：FastAPI + React

**前端**：对话界面、MCP App 容器、进度条、可视化
**后端**：WebSocket、MCP Client、LLM API、各种 Manager

**优势**：前后端分离、生态丰富、易扩展、实时更新
